# Pass C probe log — the ledger of every request the audit made against `:8081`

Append-only index. One row per probe id, in execution order, with the transcript that holds the
request, the response and the row counts. The transcripts are the primary artefacts; this file exists
so a reviewer can answer "did the audit actually run that?" without reading fourteen files, and so
every claim in `lens-L3/L4/L5/L8/L9.md` can be traced to a numbered probe.

Everything below was executed against the Postgres overlay container
(`apoorvasetu-audit-pg`, image `apoorvasetu:audit-pg`, commit `794e54c`, app on `:8081`, database on
the container-internal network — `docker-compose.postgres.yml` publishes no host port for `db`, so
all SQL ran through `docker exec apoorvasetu-db-1 psql`).

## Rules the rounds were written to obey

- **Reversible or rolled back.** Every write probe captured the affected row(s) *before* the request,
  restored by primary key afterwards, and re-checked field-by-field (`round13:P-68` prints
  `total field differences: 0`; `round13b` re-checked all seven seeded undertakings — `mismatches: 0`).
  Probes that could not be undone through the application were run inside `BEGIN … ROLLBACK`
  (`round9:P-48`, `round9b:P-50`).
- **Nothing destructive executed.** `POST /api/admin/reset` was never called with a session
  (`ALLOW_DEMO_RESET` is absent from the container environment); `docker compose down -v` was used
  only between probe groups, and re-seeding was verified by row counts.
- **Writes only under `docs/audit/`.** Cookie jars, capture JSON and fixtures lived in `%TEMP%`; the
  closing line of each round prints `git status --porcelain` outside `docs/audit/` (one `coverage/`
  entry, generated by Stage 0's coverage run, never by a probe).
- **Secrets never echoed.** No transcript prints a password, a `DATABASE_URL` value or the signing
  secret; probes that involved credentials print status codes and lengths only. **This rule was broken
  by the raw header dumps** — see "Redactions" below, which is the correction and its record.

Nothing else was changed in any transcript: no exit code, row count, status code, timestamp or `docker
stats` line was edited. `grep -rE 'apoorvasetu_sid=[A-Za-z0-9_-]{20,}|eyJ' docs/audit/` now returns
nothing, which is the check to re-run if these files are ever regenerated. The session ids that were
printed belonged to the disposable audit database, and five of them expired on 2026-11-02; the
`rememberMe` pair was still live at commit time, so it is revoked by the volume being disposable rather
than by anything in this repository.
