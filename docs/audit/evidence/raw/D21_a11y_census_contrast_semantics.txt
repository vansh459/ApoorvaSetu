8. PROBE ARTEFACTS (mine, corrected — kept so the numbers are not re-derived wrongly)
====================================================================
  (a) My first per-page census run recorded the label of the page it was about to visit, so the
      `p` field lagged the DOM by one; the rows above were re-keyed on `location.pathname`, and
      the h1 recorded with each row always matched that url.
  (b) The generic census filtered text nodes with `text.length < 2`, which silently excluded the
      43 single-character "0" cells on /pendency. The targeted colour-equality probe in §1 is
      the corrected instrument; it is also why §1 says "3 failures per page" and §1's ink-3
      count then says 46 on /pendency.
  (c) A synthetic `KeyboardEvent('keydown')` dispatched from evaluate_script did NOT close the
      case-file modal (dialogs stayed 1) although a trusted key from the browser driver did
      (dialogs -> 0). Escape results in §2 for the drawer use the synthetic path only, so the
      strict claim is "no handler observed for a synthetic Escape keydown/keyup"; the drawer has
      no keydown listener at all in source (no Escape branch in Sidebar.tsx / Header.tsx for the
      sidebar), which is the corroborating static evidence.
  (d) Programmatic `.click()` does not move focus, so an earlier "focus was not restored"
      reading was my artefact; §3 re-tests it with the opener focused first and focus restore
      confirmed.
  (e) The drawer was observed closed (x = -256) when measured in a later call than the one that
      opened it; every §2 number therefore comes from a call that opens and measures together.
      This is a harness note, not an app defect claim — no auto-close behaviour was asserted.
  (f) Route changes were driven by `history.pushState` + a dispatched `popstate` (React Router
      picks it up one tick later), because several routes are not in the SUPER_ADMIN sidebar
      list at this width. Each census re-read `location.pathname` to prove the route actually
      changed before recording numbers.
