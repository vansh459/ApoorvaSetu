## 3. Hard case: submit the application wizard with step 2 emptied

Steps: selected nothing (the radios are controlled; the pre-selected default EoA stayed, see note below),
cleared `Proposed total intake` and `Offered programs`, pressed "Review declaration", then "Submit application"
with the statutory declaration unticked, then ticked and submitted.

* Unticked declaration -> refused: toast `Agree to the statutory undertaking before submitting.` and the wizard
  stayed on step 3. The one real gate works (`SubmitApplication.tsx:40`).
* Ticked declaration -> accepted, two toasts for one action:
  `Application APP2026-1225 registered and routed via Scrutiny + EVC.` and
  `Application APP2026-1225 successfully submitted to AICTE National Portal` (one from AppContext.addNewApplication,
  one from `SubmitApplication.tsx:69`).
* Persisted record after the write (`aicte_approval_system_data_v4_apps`, 11 applications):

Against the source (`src/pages/institution/SubmitApplication.tsx:61-65`, `src/context/AppContext.tsx:774`):

* `intakeProposed: Number(proposedIntake) || 540` — an emptied field silently becomes **540 seats**, i.e. the
  system invents a number the institution never entered. Proven above: the field was blanked, the stored value is 540.
* `programs: programList.split(',').map(p => p.trim())` — an emptied textarea yields `[""]`, stored verbatim and
  later rendered in the officer's table and in reports.
* `remarks` is a fixed sentence asserting "complete fees and affidavits" for every application of this type,
  entered by no one.
* `documents` is pre-populated with an `Application Form` row stamped `uploadedOn` today
  (`AppContext.tsx:774`) although no file was attached — in a product whose differentiator is document verification,
  the record claims an upload that did not happen.

Note on the radio selection: the step-1 cards are React-controlled radios. `checked` set through the native
property + a `change` event did not move React state, so the default `Extension of Approval (EoA)` was submitted.
That is a limitation of this probe, not a defect in the app — `.click()` is the correct driver.
