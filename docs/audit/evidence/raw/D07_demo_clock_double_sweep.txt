## Root cause (static, matches the observation)

* `AppContext.tsx:2244` — `setDemoClockOffset` schedules `runSweepRef.current()` itself, and
  `AppContext.tsx:2096-2099` re-runs the sweep on every `applications` change. Advancing the clock
  calls `setApplications(...)` **and** schedules a sweep, so two sweeps execute in the same tick.
* `AppContext.tsx:2022` `const state = sweepStateRef.current;` + `AppContext.tsx:2032`
  `setAlerts(result.alerts)` — the second sweep reads a snapshot whose `alerts` array does not yet
  contain the first sweep's rows, then *replaces* state with `[...createdAlerts, ...workingAlerts]`
  (`src/workflow/alerts.ts:437`). The first generation is dropped from the repository
  (`repository.upsertAlert` at `AppContext.tsx:2038` had already written it), so the write is lost
  but its audit rows are not.
* `src/workflow/alerts.ts:426-433` — an Open alert is auto-resolved whenever its `dedupeKey` is not
  in the current candidate set, and `alertKey` includes the **tier**. Any tier progression
  (`Approaching -> Due Today -> Breached -> Expired`), any `autoEscalationDays` change in
  `/admin/system-config`, or any clock change therefore emits
  `ALERT_AUTO_RESOLVED … "closed because the underlying deadline condition cleared"` for a case that
  is still, and more, overdue.
* The 60 s interval at `AppContext.tsx:2102` re-runs the same non-idempotent pass unattended, so the
  churn continues during a demo without anyone clicking.

## Impact

* Integrity: the audit trail references alert ids that no longer exist (`ALT-MVY2BHNM-*`), and
  asserts "condition cleared" for cases that are breached. The trail is the artefact a regulator
  would read; `/admin/audit-logs` and its CSV export present it as fact.
* Demo path: the +14d escalation story the presenter demonstrates disappears after one sweep pass or
  one reload, and `Open` silently changes 16 -> 6.
* Not affected: approval/rejection correctness. `runSweep` cannot change a decision
  (`alerts.ts` never writes stage/status; the Alert Center notice "They never approve, reject or
  alter an application" holds).
