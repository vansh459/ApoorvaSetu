Why this is a defect and not a rounding artefact
a) It is self-triggering: the "Valid" KPI tile is itself the button that switches the list to
   the chip predicate — `onClick={() => setValidityFilter('Valid')}`
   (src/pages/Documents.tsx:454). A user clicks the tile that says 6 and the table renders 4
   rows, with no "showing 4 of 6" cue. The page contradicts itself on demand.
b) One instrument is counted twice. DOC-504 and DOC-508 carry the same expiry (2028-03-15)
   and DOC-508 is DOC-504's renewal successor; the KPI reports both as separately valid
   records, so "Valid 6" overstates the number of distinct valid instruments by up to 2
   (DOC-504/508 pair and DOC-509/510 pair).
c) DOC-508 is status 'Pending' — never verified by an officer — yet is bucketed under
   "Valid / No action required". Verification state is not part of the tier predicate at all
   (src/workflow/documents.ts:245-251), so unverified and rejected originals share the
   "no action required" tile.
d) The rest of the codebase follows the chip rule, not the KPI rule:
   src/workflow/alerts.ts:232-236 skips `document.renewalOfId` rows when generating expiry
   alerts. So the KPI tile is the only consumer that counts successors, which makes the
   mismatch a summariseDocuments() bug rather than a design choice.
e) The same skewed summary is exported: src/pages/Reports.tsx:112 calls
   summariseDocuments(appDocuments, ...) and src/workflow/reports.ts:247-248 builds the
   document register with .filter(isActiveDocument), so the "Valid" figure that leaves the
   product in CSV carries the double count.

Latent sibling (suspected, not reproduced this pass)
   src/workflow/sla.ts:147-148 — `documentExpiry()` returns `{ tier: 'Valid', daysLeft: +Infinity }`
   when `parseDate(expiryDate)` fails, i.e. a missing or malformed expiry date is reported as
   "Valid — No action required" rather than "unknown". All 10 seeded rows parse cleanly, so no
   live misclassification was observed; the confirming probe is to clear the expiry field on
   upload (see D-17) and check the tile. Marked suspected.

Recommended fix
   Make `summariseDocuments` take the same membership predicate as the list filter — skip
   `isRenewalRecord(doc)` rows (or count them only in a dedicated "renewals" bucket), and drop
   `status === 'Rejected'`/'Pending' from the "No action required" caption. Then make the total
   tile's caption state what it includes (e.g. "10 records incl. 1 superseded, 2 renewal
   copies") so the tier buckets no longer look like they should sum to it.
   Effort: S. Touches src/workflow/documents.ts:230-261 plus the tile captions at
   src/pages/Documents.tsx:440-479. Regression test: assert
   summariseDocuments(seed).valid === seed.filter(matchesFilter(doc,'Valid')).length for the
   shipped demo data.
